01 / The question

Same task.
A richer distribution.

Push-T offers a focused setting for learning contact-rich manipulation. Push Any Letter expands the object distribution to all 52 uppercase and lowercase ASCII letters, with different contours, holes, symmetries, and contact opportunities.

03 / Research directions

One environment.
Three ways to study learning.

Imitation learning

Train on planner demonstrations and compare behavior cloning, diffusion policy, flow matching, and an ACT-style model. Inspect success by letter and angle, with both state and image observations.

Reinforcement learning

Use the Gymnasium environment to learn through interaction, or initialize from demonstrations and fine-tune. Study sample efficiency, exploration, and robustness across object geometries.

World models

Compare MLP, GRU, and state JEPA models without velocity or task goals. Inspect prediction errors and recorded rollouts in the world-model report.

04 / Evaluation

Compare learning.
Test the dynamics.

Within a specified training distribution, compare algorithm baselines on task performance, training efficiency, and prediction accuracy.

  • Imitation learning & reinforcement learning. Compare success rates and training efficiency across algorithm baselines under matched training distributions and evaluation conditions. Measure how performance changes with training data, environment interactions, and compute.
  • World models. Evaluate how accurately state–action inputs predict the next state and longer sequences of states. Examine whether predictions capture contact events and their effects on object motion, including translation and rotation, and how dynamics errors accumulate over time.
05 / Start exploring

Run it.
Change the letter.

A CPU-based 2D simulator that runs on macOS. Python 3.9+ for simulation; Python 3.10+ for optional training dependencies.

python -m push_any_letter.app --letter Q

Experiment 02

World models

World models
No velocity · No target · V1 data

Does history help
predict motion?

We omit velocity from the input and use four recent states and past actions to supply motion context. We expected this history to help recover movement trends. On V1, the four-frame model instead has larger rollout errors than the single-frame control.

25.50 vs 41.69

Single-frame vs four-frame · position error in pixels

100-step prediction · held-out V1 trajectories

Inputs and prediction. Both models receive letter identity, pusher and object positions, object orientation encoded as sine/cosine, and the current absolute pusher-target action. The history model adds the preceding three states and actions. Both predict the next state; neither receives velocity, a task goal, reward, or images.

Data split. V1 contains 6,240 episodes and 4,736,343 transitions in total. Within each letter–angle condition, slots 00–07 train, 08 validates, and 09 tests: 4,992 / 624 / 624 whole episodes. Test letters and goal angles are familiar; trajectories are held out.

Matched training. Three 256-unit MLP layers, a letter embedding, and 30,000 updates per model, with the same sampling seed. The objective combines one-step prediction with a five-step rollout term every fourth update. One seed was tested. Checkpoints are selected by 50-step validation position and angle error.

Shared protocol. 124,800 V3 episodes; 99,840 / 12,480 / 12,480 whole-episode train / validation / test split. Letter ID, positions, orientation and actions only. Each model trains for 100k updates with batch size 1,024; checkpoints are selected by 50-step validation error. Curves use a fixed validation subset.

State JEPA. An action-conditioned latent predictor with an EMA target encoder, variance and state-reconstruction losses, and a residual state head. This is a state-based adaptation, not a reproduction of V-JEPA 2. Charts compare the shared state loss, not the different total objectives.

Limits. One seed; JEPA has 484k trainable parameters versus 141–159k for the baselines. Test angles are in the V3 training distribution. Larger data, training budgets and test splits differ from V1, so this is not an isolated data-scaling experiment. Long rollouts still accumulate error.
